# Private handoff: register containment, then prove disposal

**Dummy input only.** Earlier normal/minimized-window closure checks passed, but the replacement broker-backed capture route still requires restricted-session integration, reload and a direct integrated dummy-only handoff. ## Prepare before exposure

Preserve the selected Ubuntu GNOME desktop and existing Firefox profile. Keep Desktop Sharing/grants and unrelated apps unchanged. Drain ordinary tool calls, shell shortcuts and external observation/background recording. Obtain authorization to dispose only the newly created dedicated source containers.

Call `private_handoff_guard` **directly**, not through codemode or another wrapper:

```json
{"action":"prepare","disposable_sources":true,"firefox":true,"capture":{"output":"/absolute/owned/private/new-value"}}
```

At least one source is required. Capture may include `fields` and `root` for named broker fields and a namespace. Use a new trusted absolute metadata-receipt destination, outside Git or verified ignored. The guard creates the Firefox blank in the existing profile and supervised capture; do not launch the capture separately, supply arbitrary commands or adopt existing windows.

Preparation durably pauses before source creation. Capture is masked and disabled until the exact host binding is registered and activated. Record the returned host handoff ID. `ready:false`, timeout or unknown outcome means **no private input**; leave observation blocked. `ready:true` means preparation completed; it does not supply missing task/disposal authorization.

Emergency `begin` or `/private-handoff pause` is unbound protection. It is not a handoff preparation route and cannot be cleared by human confirmation.

## Human entry

After preparation returns `ready:true`, instruct the human to stay inside the prepared dedicated Firefox window and enter only `NONSECRET-DUMMY` in **Private value capture**, then click **Save privately**. Real input remains prohibited. No human done/receipt/resume authorizes release. Do not move/copy input into unrelated pre-existing windows or other containers.

The capture clears and closes after successful save. Chat done/saved, a checkbox, successful storage and a receipt are not disposal evidence. Ordinary tools remain blocked, including screenshots, accessibility trees, DOM, clipboard, shell/file reads, generic browser/desktop actions and nested wrappers. `include_screenshot:false` is still observation. After an error, do not inspect the private UI through another route.

## Agent closes; host verifies

Call directly:

```json
{"action":"close","handoff_id":"CURRENT_32_HEX_HOST_ID"}
```

The host loads the persisted exact binding. Capture release requires original recursive cgroup emptiness and worker exit; Firefox release requires exact context/client-window disposal in the original persistent broker session. Both require native source absence twice and preserved original baselines. It closes only registered exact sources. It never kills unrelated processes, substitutes a browser/profile or accepts replacement IDs.

Missing/replaced authority, pending preparation, save prompts, unexpected windows, replaced originals, unknown close responses or timeout remain paused. A disappearing or hidden native window is not enough. A dead broker/guardian is unknown, not disposed. Only `closure_verified:true` and `paused:false` permit ordinary tools to resume. `cleanup_complete` is separate bookkeeping.

Check opaque storage receipt and actual worker exit status separately, without reading broker values through model-visible tools. The capture UUID is distinct from the host handoff ID. Its schema-3 reference receipt plus broker confirmation proves storage only, never source closure. See [capture instructions](../templates/README.md). No raw file/stdin credential-transfer route remains in the capture helper.

## Interrupted state and limits

Binding/pending obligations survive compaction, reload and restart. There is no human resume, lease expiry, marker deletion, administrative bypass, migration or rebind route. Interrupted/unbound/legacy/unknown state stays blocked. Stop and report the missing authority rather than adopting a fresh source as proof.

Firefox allows one BiDi session. Broker loss can leave it occupied and prevent fresh preparation. Do not restart the existing browser or reconnect/adopt its session without separately assessed permission; neither action would prove disposal of the lost original authority.

This is dispatcher enforcement, not an OS sandbox or universal secret detector. Old/extensions-disabled Pi processes, other agents, trusted extension-side I/O, external recording, clipboard/history, other devices and malicious same-UID changes remain outside coverage. Verified disposal does not erase persistent storage/history. If exposure occurs, stop observing, notify without values and recommend separately authorized rotation/revocation; do not reopen payloads to prove exposure.
